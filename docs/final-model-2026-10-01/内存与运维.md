# 全服务资源测量与运维

这是 2026-10-01 行情／2026-10-02 交付的历史验证材料。当前模型以 [2026-10-04 指标模型](../indicator-model-2026-10-04.md)、AGENTS.md 和现行配置为准；以下版本、参数与结论保留其原有日期。

用户通知明确确认OOM触发自动重启。泄漏、峰值及配置的实际贡献需要指标验证；本次不把浏览器heap、Node old-space或多个进程各自最大值相加当成容器峰值。

## 已实施预算和生命周期

| 资源 | 运行/排队上限 | 方式 |
|---|---|---|
| quote fetch | 2+2 | 按ticker/option共享未完成任务；结果带原始代际 |
| quote controller | 2+2 | 等待超时abandon ApplyToken，不能晚写新缓存 |
| interval fetch | 4+4 | quote不在同池递归等待；ticker+interval共享，保留超时占额 |
| market source | 4+12 | 一次完整watchlist事务共用市场snapshot |
| auxiliary fetch | 2+2 | 搜索等有界后台请求 |
| quote RAM | ≤68条且JSON≤8MiB | TTL/LRU，读写清过期，当前watchlist/必要基准保留，超限用持久缓存 |
| search/news | 128条/1MiB；60条/4MiB | 同样TTL/LRU/字节预算 |
| 重型事务/Node | 同时一个 | FULL_REFRESH_RUN_LOCK + NODE_PROCESS_LOCK，所有残留IO排空后启动子进程 |

网络连接3s/读取5s，包含yfinance metadata实际socket；fallback有限，不再用同一完整fetch当quote-only重试。池预算不会因future等待超时释放，同一重型任务未结束时不再开一份。较早代际的quote/interval不能混入后来的快照。

完整手动/小时刷新仍真正force每个当前ticker，两只一批，15批覆盖29、30批覆盖60。UI共用一个promise/单调代际，数据→三期限→DOM→paint后才结束Refreshing并提交server freshness，ET使用America/New_York。失败保留上次成功页面与Last Refresh，下一小时可重试。

compact HTTP输出仅存一个quote副本，逐ticker序列化；没有复制三个analysis别名。EOD只保留manifest/逐ticker临时输入、有限underlying共享、逐行输出；三期限共用canonical，最终SQLite一次事务。清RAM cache不是证明RSS立刻下降；单独清引用的实验没有稳定降低峰值，因此不宣传其百分比。没有把周期GC或重启当修复。

已删除没有被 Flask 或启动入口调用的旧 HTTP Handler 和未使用的 debug quote helper，避免留下第二套刷新代码。

## 测量条件与限制

本地macOS、Python3.12.14、Node24.19.0；Gunicorn1worker/2threads/timeout120，与目标部署命令一致。冻结29份真实10y Daily/native365d payload，在相同输入/runtime上对比起始commit及修改后。60只是同payload尺寸的模拟容量边界（额外AUDIT身份，仅离线fixture，未进入生产watchlist/模型）；不是60个真实供应商抓取证明。

每50ms采样同一时刻Gunicorn master、worker及全部Node descendants RSS总和；每进程值和原始samples可查。Linux工具会读取所在cgroup current/peak/max与RSS/PSS；此机器没有这些指标，文件页缓存记账、512MiB实际container限制、0.5CPU与Render流量均**未验证**。RSS共享页也可能被重复计入，不能等同cgroup memory.current。

场景包括启动/空闲、完整刷新、连续5轮、32次短等待超时/残留恢复、EOD与3个缓存访问并发；另做20轮60容量和真实供应商29只单轮full+EOD。EOD测试钟设在同一交易日16:30，payload实际采集在盘后；这是资源/完整性模拟，不能宣称精确16:30行情回测。

完整对比及phase表见下方自动生成表。修改前29/60的超时场景曾同时活跃32抓取线程；修改后上限2。真实29源测试完成29 quote/58 interval/12 market/1 auxiliary任务，结束均无待办，EOD87行成功。20轮容量测试EOD180行成功，cached quote19条/约8MiB，线程6，超时后保留正在运行的2任务并在Node启动前排空。

20轮60次刷新后进程RSS180.66→181.45MiB，约+0.8MiB，存在阶梯/平台但仍有小幅单调增长，**不能宣称已证明长期无泄漏**。任务/缓存字节与条数保持边界。线上需持续几天采样区分allocator保留与真正长期增长。新代码本地进程峰值留出目标512MiB的20%工程余量，但不能把这个目标当已验证容器余量或永不OOM保证。

## 发布后由服务容器验证

启用RESOURCE_METRICS_ENABLED后，health及`service_resources`日志含cgroup/RSS/PSS、线程、每池running/queued、RAM条数/JSONbytes，Node start/end、refresh start/end和EOD handoff bytes。在Render查看同一时刻Metrics与日志，记录memory.max实际值、启动/空闲/手动/小时/超时/连续运行/16:30及访问并发的current/peak；文件cache也以cgroup为准。目标峰值≤实际限制80%，不合格则保留测量证据继续修生命周期/必要实例预算。不要重置memory.peak后把更早OOM峰值藏掉。

核对publichealth中的实际Python版本、cache/DB路径、Node命令；检查完整watchlist的live_success/failed/deferred（应无deferred）、server freshness/ET显示以及失败后的恢复。遇到无原生4H能力保持具体缺失；更换供应商、付费或改变timeframe方法需另作明确决策。

EOD由服务端16:30 America/New_York执行；当日已有合格full-refresh可共享代际，仍查Daily日期。周末/假日跳过；个别stale/unavailable写三期限明确行，核心缺失保留partial；全部成功状态与行同事务，重复同日UPSERT，失败重试不留下部分成功。正常Dashboard不开历史库。持久路径优先env，否则/var/data/历史记录.sqlite。导出及完整移除见[历史说明](../../历史记录/README-历史记录.md)。

新数据库单日29行组87条约2.7MiB，60行组180条约5.4MiB（包括SQLite页/索引，不等于严格每日增量）。1GB磁盘需监控历史库实际增长与cache/temp峰值；不能自动删除旧历史换空间。接近容量时先离线导出/备份并作明确容量决策。测试完成后的临时进程/数据库不作为常驻生产history。
